# Local DFT Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan inline. The user has already authorized implementation.

**Goal:** Import explicit atomic structures, run real Quantum ESPRESSO calculations locally, inspect convergence and retain reproducible evidence.

**Architecture:** Electron manages immutable job directories in its local user-data folder. ASE imports structures and writes QE input; a Python worker runs QE in a dedicated WSL distribution and parses QE XML. The renderer saves configuration and job references in existing v1 projects.

**Tech Stack:** Electron, Three.js, ASE, Python 3, Quantum ESPRESSO, Ubuntu 24.04 WSL2.

**Spec:** The approved first stage in this conversation: Si and monolayer MoS2 before atomically specified interfaces or device coupling.

## Global Constraints

- All calculations and local file contents stay on this computer.
- Initial model: neutral, nonmagnetic, fixed ions, PBE, scalar-relativistic USPP; supported pseudopotentials Si/Mo/S.
- CIF, POSCAR and extended XYZ are read by ASE, not an application-specific parser.
- Band-path energies are distinct from a uniform-grid sampled Kohn-Sham gap and from device E(x).
- No automatic material-database replacement or experimental/optical/quasiparticle claims.
- SCF termination, parameter sensitivity, and physical applicability are reported separately.

## Review Focus

- Invalid or unsupported imported structures must not replace the current structure.
- Parameter or project changes must never silently associate old results with new input.
- Cancellation and application restart must retain evidence and permit an explicit retry.
- QE failure or absent XML must never produce a successful task.
- A transferred project may reference absent jobs; this must be shown explicitly.
