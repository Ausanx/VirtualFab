# VirtualFab 交互 MVP

## 开源项目观察与取舍

| 项目与依据 | 可借鉴的优势 | 对 VirtualFab 的代价或不足 | 本轮决定 |
| --- | --- | --- | --- |
| [Qucs / Qucs-S](https://github.com/Qucs/qucs-help/blob/develop/source/start.rst)：项目创建、内容区、保存文档；[Qucs-S](https://github.com/ra3xdh/qucs_s) 将图形界面连接多个求解器 | 项目生命周期明确，设计输入与结果视图都有固定位置 | 它的项目目录、多文档和多求解器配置用于当前单 JSON 工艺文件会增加操作负担 | 借鉴新建、打开、保存与明确的文件状态；不复制项目目录结构 |
| [FreeCAD FEM](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/FEM_Workbench.md)：建模与材料、求解、结果查看 | 将前处理、计算、后处理排成可理解的工作流 | 外部网格器、求解器的安装和配置不适合当前几何近似模型 | 保持工艺卡片、运行、结构/诊断视图的分工；不加入求解器选择器 |
| [OpenROAD GUI](https://openroad.readthedocs.io/en/latest/main/README.html#gui)：按流程阶段可视化、分析和调试，另有 Tcl 接口 | 结果可回到具体设计阶段定位问题 | Tcl 控制台和完整物理设计流程对首版材料器件用户门槛过高 | 保留诊断跳转到工艺步骤；不加入脚本控制台 |

以上“不足”是针对 VirtualFab 当前范围的适配判断，不是对这些项目的通用评价。本轮只借鉴交互思路，没有复制其代码。

## 已落地的最小工作流

1. **项目入口**：顶部提供新建、打开、保存、另存为；“新建”采用左侧当前所选模板。异质结模板使用通用名称，内置步骤仍以 Te / InON 演示。
2. **桌面文件**：Electron 主进程通过系统对话框读写 JSON；保存覆盖本次打开或保存的文件，另存为选择新文件。渲染进程只接收限定的文件操作接口，不直接获得 Node 文件系统权限。
3. **状态与恢复**：文件保存状态和未保存更改分开显示；自动缓存继续用于异常恢复。新建或打开要替换未保存内容时，可先保存、直接继续或取消。打开无效文件、取消对话框和写入失败均保留当前项目。
4. **网页兼容**：本地开发网页仍可上传 JSON；“保存”触发 JSON 下载。网页下载无法确认用户最终是否保留文件，因此不把它显示成已写入项目文件。

## 验收边界

- 当前项目仍使用 `version: 1` JSON，不改变工艺或材料数据结构。
- 真实桌面程序中完成首次保存、覆盖保存、另存为、打开、取消、无效文件隔离、新建前保存和重启自动恢复。
- 浏览器回归验证模板、导入下载、工艺编辑、图形预览和窄屏布局。
- 下一阶段仅在明确文件冲突策略后考虑最近项目和跨重启保持文件关联；多文档、脚本控制台与外部求解器暂不进入 MVP。
